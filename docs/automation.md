# Automation (local feature branch)

Automation runs only while ViceScope is open. It supports non-recursive local folders, exact YouTube video URLs, and bounded public metadata discovery from YouTube channel and playlist URLs or IDs. An exact URL may be an ordinary video or completed archived VOD; live, upcoming, restricted, DRM, and unknown live-status videos are rejected. The YouTube metadata and download calls use no browser cookies. Channel discovery uses the uploads tab by default; enable the livestream option to scan the streams tab instead. Kick, Twitch, monitoring services, and unattended upload/publication are not implemented.

1. Create or choose an existing output folder on a drive with sufficient space. The default field is `D:\ViceScope\Shorts`; the application does not create it automatically.
2. Open **Automation**, choose **Local folder**, **Exact YouTube video**, **YouTube channel**, or **YouTube playlist**, and enter its path or URL, creator, and permission evidence. Explicitly check the source authorization and choose **Add authorized source**.
3. Folder monitoring does not itself grant rights to individual files. Either approve each exact local file in Clip Editor, or separately check **I have permission to process every new video placed in this folder** when adding the source. This records an explicit folder-wide grant and attaches its ID and evidence to each newly authorized file. Previously denied or changed per-file decisions are never overwritten automatically. Use this option only when you have permission for every new file in that folder.
4. Choose the output folder, scan interval, clip count, duration, minimum highlight score, CPU thread setting, and minimum free-disk preflight. Check **Automatically generate clips** to allow processing; otherwise scans only discover items. Select **Start / resume**, or **Run now** for a single scan/processing pass.
5. Review generated clips in **Ready for Review**. They are never approved or published automatically. Stop the app only after current work finishes; stop requests are cooperative and wait for the current download, transcription, analysis, or render step.

A local file must keep the same size and modification time for at least ten seconds and then pass a hash-based rights check. This quiet period cannot prove that another program will never write again; hashes are rechecked before processing. Content hashes suppress duplicates; replacing a file creates a separate discovery record. Disabling a folder-wide grant blocks linked file processing and clears linked private-upload approvals. An individual explicit approval can be recorded in Clip Editor instead.

Jobs and sources persist in SQLite; the scheduler restarts stopped and must be started again. A single cross-process lock permits one automation worker. A crash during processing marks a job interrupted, and interrupted/failed jobs are not blindly retried because partial clips might already exist. A small bounded exponential backoff applies only to recognized transient failures before a YouTube download completes. Failures before generation can be manually retried from the job list; later failures require manual inspection.

The disk setting also monitors free space during processing and requests a cooperative stop; it is not a hard disk quota. The thread setting is passed to Whisper and FFmpeg where supported, but is not an operating-system CPU cap. The existing highlight scoring and subtitle pipeline are heuristic; review every result. Do not interpret public discovery results or this tool's source evidence field as independent legal verification.


## Channel and playlist discovery

Choose a channel ID/URL or playlist ID/URL, enter the creator and permission evidence, and add it. Discovery reads public metadata only using the bundled yt-dlp, without cookies. A discovered item does not inherit permission from the channel or playlist: select the job and use **Authorize selected exact video**, confirming that you have permission for that item. Scan again to queue it. Before acquisition the exact permission and completed status are checked again; active, upcoming, restricted, DRM-protected, and unknown completion states are not acquired. Discovery cannot guarantee that a bounded first page contains every new video. Live network discovery and acquisition require an authorized real source and have not yet been verified.

Set the scan limit, clip limit, retry limit and initial backoff in Automation. The retry policy only covers recognized transient metadata/download failures. **Retry failed job** is available only when generation never started, because an interrupted render can leave partial or complete review items. Those jobs require manual inspection; there is no automatic recovery of potentially duplicated output. During processing a monitor samples free disk space every second and requests a cooperative stop when it falls below the configured threshold. Long downloads, transcription or rendering may not stop immediately, so this is not a hard storage quota.
