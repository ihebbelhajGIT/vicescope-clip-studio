# Upstream audit and architecture

Reference: https://github.com/Bodila51/gtavi-claudecode (reviewed 2026-11-19 via GitHub raw files). Git clone failed because this environment could not connect to GitHub. README, requirements, and the named scripts were inspected through the web reader; this is a partial audit, not a complete security review.

The upstream project uses yt-dlp for search and downloading, faster-whisper for speech, signal-based moment selection, FFmpeg and ASS for rendering, and OpenCV for facecam detection. It uses unofficial Twitch web GraphQL and anonymous IRC, and downloads an OpenCV model without integrity verification. Its URL-based moment pipeline downloads media automatically, so it is unsuitable as-is for the requested source-specific authorization boundary. Its campaign checks are formatting checks, not proof of permission. No upstream code was copied or executed; no upstream license text is required for this independent implementation. The upstream repository declares MIT; that license does not grant footage rights.

The application separates SQLite persistence (`app/storage.py`), adapters and rights checks (`app/core.py`), and Qt presentation (`app/main.py`). External process execution uses argument arrays. This is a foundation: the package action is disabled because it cannot verify that an existing MP4 derives from the selected source. Future rendering must associate each output with its approved source, recheck rights and campaign limits immediately before export, validate FFprobe output, and handle cancellation safely. Avoid putting sensitive permission documents in logs.
